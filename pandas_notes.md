# Особенности работы Python и Pandas в оперативной памяти

Разбор ссылочной модели памяти, векторизации вычислений и прямое сопоставление синтаксиса Pandas с логикой SQL-запросов.

---

## Физика процессов в RAM компьютера

### 1. Ссылочная модель памяти (Капкан мутации)
В отличие от СУБД, где данные лежат жестко в таблицах на диске, Python работает в оперативной памяти через ссылки (указатели).
* Когда вы пишете `df2 = df1`, компьютер **не копирует** таблицу. Он создает второй ярлык, который указывает на тот же самый кусок памяти.
* Если вы измените `df2` (например, удалите столбец), то в `df1` этот столбец тоже исчезнет.
* **Решение:** Чтобы сделать независимую копию таблицы в памяти и защитить исходные данные, нужно явно вызвать метод копирования: `df2 = df1.copy()`.

### 2. Векторизация вместо циклов `for`
В анализе данных на Python использовать циклы `for` для перебора строк таблицы запрещено. Циклы обрабатывают ячейки последовательно, что приводит к критическому падению скорости на больших массивах данных.
* **Векторизация** — это применение операции сразу ко всему столбцу (массиву данных) на уровне процессора в один такт. В Pandas это реализовано через библиотеку NumPy (написанную на C++).
* *Пример:* Вместо цикла мы пишем маску: `df[df['salary'] > 50000]`. Движок мгновенно выделяет нужный сегмент в RAM.

## Матрица соответствия синтаксиса (SQL ──> Pandas)

Физика обработки данных одинакова, меняются только команды:

| Операция с данными | Как пишется в SQL | Как пишется в Python (Pandas) |
| :--- | :--- | :--- |
| **Выбор столбцов** | `SELECT name, age` | `df[['name', 'age']]` |
| **Построчная фильтрация** | `WHERE age > 18` | `df[df['age'] > 18]` |
| **Схлопывание / Агрегаты** | `GROUP BY department` | `df.groupby('department').agg({'salary': 'sum'})` |
| **Сшивка таблиц (Мост)** | `LEFT JOIN trans ON...` | `pd.merge(df1, df2, how='left', on='id')` |
| **Сортировка строк** | `ORDER BY salary DESC` | `df.sort_values('salary', ascending=False)` |

## Системные ошибки и предохранители

1. **Капкан типов данных (`SettingWithCopyWarning`):**
   * *Суть:* Возникает, когда вы пытаетесь изменить кусок таблицы, который был получен фильтрацией без явного использования `.copy()`. Python не понимает, менять ли исходную таблицу или её срез.
   * *Предохранитель:* Всегда отделять отфильтрованные данные в новую переменную через `.copy()`.
2. **Капкан склеивания (`Merge Explosion`):**
   * *Суть:* Аналог раздувания строк при `LEFT JOIN` в SQL (связь «многие-ко-многим»). Если ключи дублируются в обеих таблицах, объем RAM забьется дубликатами строк, и скрипт упадет по ошибке `Out of Memory`.
